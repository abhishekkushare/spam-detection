SMS Spam DetectionIntroduction

1. Introduction

The project classifies SMS from a Twilio account. Each message is labelled Ham (legitimate) or Spam. It is a teaching prototype: one Flask process, one saved neural network, and an optional MySQL table. It is not a production filter.

2. Features

  • Sign in with a Twilio Account SID and Auth Token.
  • Read recent messages from that account.
  • Score each body with the saved Keras model.
  • Split the inbox into ham and spam.
  • Optionally store a name, SID, and token in MySQL.
  • Light and dark theme, remembered in the browser.
  • Shared header and a three-column footer with social icons.

3. Who it is for

A student or developer who wants to see a web form, an external API, a database, and a classifier in one small system. Written by Abhishek Kushare.

6. How the application works

  1. Home collects the Twilio Account SID and Auth Token.
  2. Flask asks Twilio to fetch that account. A database row is optional.
  3. The session stores the display name and the SID. The header then shows that name, Sign Out, and Register.
  4. Inbox streams messages and keeps the first 10.
  5. process_sms() maps the text to 8 token ids.
  6. If the sigmoid output is greater than 0.5, the row is spam. Otherwise it is ham.

Model in one paragraph

spam.csv has 5,572 messages (4,825 ham, 747 spam). An 80/20 split feeds a Keras network: embedding of size 24, flatten, dense layers 500 / 200 / 100, dropout 0.5, and a sigmoid output. Optimizer RMSprop, loss binary cross-entropy, early stopping patience 10. Notebook accuracy on the test split is about 0.982. Spam recall is about 0.89. Full notes are in docs/MODEL.md.

Database

Database SMS_SPAM_DETECTION, table users: authid (SID), id, name, tno (Auth Token). Column order matters because sign-in reads the SID from the first column and the token from the fourth.

13. Security notes

  • Do not commit .env, Account SIDs, or Auth Tokens.
  • tno stores a token in plain text. Fine for a local demo only.
  • The Twilio client is process memory. One signed-in user at a time, and Sign In again after a restart.
  • Flask debug mode stays off outside your own machine.

14. Future enhancements

  • Load the model once at startup.
  • Fetch only the 10 messages the inbox shows.
  • Show the score beside each message.
  • Stop storing tokens in plain text.
  • Offer prediction as a small REST call.
